## Usability principles

These principles test whether a user can complete each use case. Name the principle in each finding.

### Usability heuristics

Jakob Nielsen's ten heuristics:

1. **Visibility of system status.** The user knows what is happening: loading, saved, failed, or waiting. Feedback appears within one second.
2. **Match with the real world.** The screen uses the user's words and concepts, in the order the user expects. No internal term appears.
3. **User control and freedom.** Each action has a clear exit: cancel, undo, or back.
4. **Consistency and standards.** One meaning has one word, one component, and one position.
5. **Error prevention.** The design prevents an error before it needs a message: constraints, good defaults, and a confirmation before a destructive action.
6. **Recognition over recall.** The screen shows the options, the values, and the context. The user never remembers information from another screen.
7. **Flexibility and efficiency.** Frequent users have faster paths, such as defaults and shortcuts, at no cost to new users.
8. **Aesthetic and minimalist design.** Each element supports the task. Each extra element competes with the elements that matter.
9. **Recognise, diagnose, and recover from errors.** An error message states what happened, why, and what to do next, in plain words.
10. **Help and documentation.** Help is short, in context, and tied to the task.

### Laws of UX

| Law | Statement | Apply as |
|---|---|---|
| Fitts's law | The time to reach a target depends on its distance and its size. | Make the main action large, and place it near the content it acts on. |
| Hick's law | Decision time grows with the number and the complexity of the choices. | Show fewer options at each step. Put rare actions in a menu. Recommend a default. |
| Jakob's law | Users expect a product to work like the products they already use. | Follow the product's patterns and common web patterns. |
| Miller's law | Working memory holds about seven items. | Group content into chunks. The number is no hard limit. |
| Tesler's law | Each system has complexity that cannot be removed. | Move complexity from the user to the product: defaults, inference, and automation. |
| Doherty threshold | Productivity rises when the system responds within 400 ms. | Show feedback within 400 ms: an optimistic update, a loading state, or a skeleton. |
| Aesthetic-usability effect | Users rate an attractive design as easier to use. | Misalignment and inconsistency reduce trust in the product. |
| Von Restorff effect | Users remember the item that differs. | Make the one important item differ. When several items differ, none stands out. |
| Serial position effect | Users remember the first and the last items in a series best. | Put the key items first and last. |
| Peak-end rule | Users judge an experience by its most intense moment and its end. | Give the end of a flow and its hardest moment, such as a failed payment, the most care. |
| Goal-gradient effect | Motivation rises as the goal gets closer. | Show progress in a flow with several steps. |
| Zeigarnik effect | Users remember tasks they have not finished. | Show what remains, and let the user return to it. |
| Postel's law | Accept varied input, and send precise output. | Accept common input formats. Show values in one format. |
| Occam's razor | The solution with the fewest assumptions is preferred. | Remove elements until the design stops working, then restore the last one. |
| Pareto principle | About 80% of the effects come from 20% of the causes. | Design the most common use cases first. |
| Cognitive load | Each element uses part of the user's attention. | Remove what the task does not need. |
